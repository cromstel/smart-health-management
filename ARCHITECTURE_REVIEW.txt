# Smart Health Management System - Architecture Documentation

## Overview

The Smart Health Management System (SHMS) is a comprehensive healthcare management platform built with modern web technologies. It provides a complete solution for managing patient records, appointments, pharmacy operations, financial transactions, and administrative functions with role-based access control.

## System Architecture

### High-Level Architecture

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   Frontend      │    │   Backend API   │    │   Database      │
│   (React SPA)   │◄──►│   (Node.js)     │◄──►│   (MySQL)       │
│                 │    │                 │    │                 │
│ • React 19      │    │ • Express.js    │    │ • 30+ Tables    │
│ • TypeScript    │    │ • TypeScript    │    │ • RBAC Schema   │
│ • Tailwind CSS  │    │ • JWT Auth      │    │ • Healthcare Data│
│ • Vite          │    │ • REST API      │    │                 │
└─────────────────┘    └─────────────────┘    └─────────────────┘
```

### Technology Stack

#### Frontend
- **Framework**: React 19 with TypeScript
- **Build Tool**: Vite 6.x
- **Styling**: Tailwind CSS v4
- **State Management**: React Context API
- **Routing**: React Router DOM v7
- **HTTP Client**: Fetch API (custom wrapper)
- **Code Splitting**: React.lazy with Suspense
- **PWA**: Vite PWA plugin with offline support

#### Backend
- **Runtime**: Node.js
- **Framework**: Express.js
- **Language**: TypeScript
- **Authentication**: JWT with httpOnly cookies
- **Authorization**: Role-Based Access Control (RBAC)
- **Validation**: Express Validator
- **Security**: Helmet, CORS, Rate Limiting
- **Caching**: Redis with automatic invalidation
- **Database**: MySQL 8.0+ with connection pooling

#### Database
- **Engine**: MySQL 8.0+
- **Schema**: Normalized relational design
- **Indexing**: Optimized for query performance
- **Connection Pooling**: Configurable pool size
- **Migration**: SQL-based migration system

#### Infrastructure
- **Deployment**: Docker containers
- **Reverse Proxy**: Nginx (production)
- **SSL/TLS**: HTTPS with Let's Encrypt
- **Monitoring**: Application logs and error tracking
- **Backup**: Automated database backups

### Database Performance

#### Indexing Strategy
- **Primary Keys**: All tables have BIGINT primary keys
- **Foreign Keys**: Indexed for JOIN performance
- **Composite Indexes**: Multi-column indexes for complex queries
- **Partial Indexes**: Conditional indexes for filtered queries
- **Full-text Search**: Optimized for text-based searches

#### Query Optimization
- **Connection Pooling**: Configurable pool size (default: 50)
- **Prepared Statements**: Parameterized queries prevent SQL injection
- **Batch Operations**: Efficient bulk data operations
- **Caching Layer**: Redis caching for frequently accessed data

## Security Architecture

```
1. User Login → Password Validation
2. JWT Token Generation → httpOnly Cookie
3. Session Management → Automatic timeout
4. Token Refresh → Secure renewal
5. Logout → Token invalidation
```

## API Architecture

### RESTful Design Principles
- **Resource-Based URLs**: `/api/patients`, `/api/appointments`
- **HTTP Methods**: GET, POST, PUT, DELETE appropriately
- **Status Codes**: Standard HTTP response codes
- **Content Negotiation**: JSON request/response format

### API Response Format
```json
{
  "success": true,
  "data": { ... },
  "message": "Optional message",
  "pagination": { ... } // For list endpoints
}
```

### Error Handling
```json
{
  "success": false,
  "error": "Error message",
  "code": "ERROR_CODE",
  "details": { ... } // Optional error details
}
```

### Rate Limiting
- **General API**: 100 requests per 15 minutes per IP
- **Authentication**: 5 attempts per 15 minutes per IP
- **File Upload**: 10 uploads per hour per user
